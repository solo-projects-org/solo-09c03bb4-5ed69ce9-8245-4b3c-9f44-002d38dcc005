# 展图授权清单管理

博物馆数字展览团队使用的网页工具：导入拼版展图与原图的对照关系、分批补录原图授权，
在**每张原图都有有效商用授权且编辑确认署名**后，才能下载列有「原图号、授权号、署名」的清单。
授权被撤回时自动换用同署名有效授权，否则停供并等待编辑确认替代清单。

支持供图机构一次发来的一整包授权材料：**ZIP 材料包**内含若干扫描件 PDF 与一份授权 CSV，
CSV 沿用原列并增加「PDF文件名」列；扫描件按内容去重保存，授权页可下载原件。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问 http://localhost:8000 。SQLite 数据与扫描件保存在名为 `app-data` 的卷中
（容器内 `/data/app.db` 与 `/data/files`），服务重启、容器重建后状态不丢。

### 本地开发

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

数据库路径由环境变量 `EXHIBITION_DB` 指定，默认 `data/app.db`；扫描件目录由
`EXHIBITION_FILES` 指定，默认与数据库同级的 `files/`。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `EXHIBITION_DB` | `data/app.db` | SQLite 文件 |
| `EXHIBITION_FILES` | 数据库同级的 `files/` | 扫描件存储目录 |
| `EXHIBITION_MAX_ZIP_MB` | `2048` | 上传 ZIP 大小上限 |
| `EXHIBITION_MAX_PDF_MB` | `512` | 单个扫描件解压后大小上限 |
| `EXHIBITION_MAX_EXTRACT_MB` | `4096` | 整包解压后总大小上限（防压缩炸弹） |

## CSV 格式

均支持 UTF-8（含 Excel 的 BOM），列名支持中文或英文别名。

**展图-原图对照 CSV**（首页导入，可重复导入，幂等）：

```csv
展图号,展图名称,原图号
EXH-01,唐代壁画拼版,ORG-001
```

**授权 CSV**（可分批补录，保留原入口）：

```csv
授权号,原图号,是否允许商用,署名
LIC-001,ORG-001,是,摄影：张三
```

**材料包授权 CSV**（放在 ZIP 内，沿用原列，另加 PDF文件名 列）：

```csv
授权号,原图号,是否允许商用,署名,PDF文件名
LIC-001,ORG-001,是,摄影：张三,scan_org001.pdf
LIC-002,ORG-001,是,摄影：张三,scan_org001.pdf
```

「是否允许商用」接受 `是/否/允许/不允许/true/false/1/0` 等取值。
示例数据见 `sample_data/`，其中 `licenses_package.zip` 是可直接上传的材料包。

## 功能与规则

- **导入（原入口）**：对照 CSV 建立展图与原图关系；授权 CSV 分批补录，授权号唯一——
  重复导入的行直接跳过，**重传不能恢复已撤回的授权**。
- **材料包（ZIP）导入**：
  - 包内 PDF 逐个**按块**流式解压、计算 SHA-256 并按内容去重；相同内容只保存一份文件，
    多条授权引用同一 PDF 时共用同一份存储（`files` / `license_files` 表）。
  - CSV 的「PDF文件名」按文件名绑定包内原件（允许带目录前缀，Windows 反斜杠亦可）。
  - **新授权**：授权号不存在时连同原件一起入库。
  - **补件（旧授权补挂原件）**：授权号已存在但尚未挂原件时，必须核对
    **原图号、商用标记、署名**与已存数据完全一致；一致才补挂，任一不符即同号冲突。
  - **重传**：已挂原件的授权再次导入，还要核对 **PDF 内容**——本包引用的全部扫描件
    与已挂内容逐份相同才视为重传成功，否则整包失败。
  - **撤回是终态**：已撤回的授权在包内出现时既不补挂、也不恢复，仅在结果中提示原因。
  - **缺件 / 同号冲突 / CSV 错误**都会让整包不生效，并在页面说明具体原因
    （哪一行缺哪个文件、哪个授权号哪一项不一致）。
  - **原子性**：全部校验通过后，新授权与原件挂接在同一事务内提交。导入失败、保存中断
    或浏览器断开时数据库整体回滚，本次新落盘且未被引用的扫描件也会删除，
    重启后可直接重传整包。
  - **清单可用性**：新授权必须与原件一起成功入库（提交）后，才会被清单同步选用；
    提交前的中间状态不会影响展图清单。
- **原件下载**：授权页每份已挂原件都有「下载原件」链接
  （`GET /licenses/{license_id}/files/{file_id}`），返回原始 PDF。
- **下载条件**：展图的每张原图都有有效（未撤回且允许商用）授权，且编辑已确认署名，
  才可下载清单 CSV（列：原图号、授权号、署名）。下载请求在事务内实时复核，停供返回 409 及原因。
- **撤回（网页操作，终态）**：
  - 撤回使用中的授权时，若该原图还有**同署名**的有效商用授权 → 自动换用，确认状态保留，下载不受影响；
  - 只有**不同署名**的有效授权 → 换用并置为「待确认署名」，展图停供；
  - 完全没有有效商用授权 → 标记「缺授权」，展图停供（不允许商用的授权不会被选用）。
  - 停供页面明确指出哪些原图缺授权、哪些需要确认新署名。
- **编辑确认**：编辑在展图详情页核对当前清单并署名确认。确认在事务内重新校验：
  若清单中的授权在此期间被撤回或清单已变更（撤回与确认交错），拒绝确认、维持停供并提示重新核对；
  缺授权时确认无效，需先补录授权。
- **持久化**：全部状态存于 SQLite，扫描件存于文件目录（同放在 Docker 卷中），
  撤回与确认交错、服务重启后，下载仍只使用当前有效且已确认署名的清单。
- **页面**：`/` 展图列表与两种导入入口；`/exhibitions/{id}` 清单、停供原因、确认表单、确认记录；
  `/licenses` 授权列表（有效/已撤回/使用中、原件下载）与撤回操作。
- **JSON API**：`GET /api/exhibitions`、`GET /api/exhibitions/{id}`、`GET /api/licenses`
  （授权含 `files` 列表），便于数字展览团队程序化处理。

## 自测

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

`tests/test_flow.py`（9 个原有用例）覆盖：导入 → 确认 → 下载、同署名自动换用、
不同署名停供后重新确认、缺授权停供、重传不恢复撤回、撤回/确认交错、重启持久化、
对照幂等、页面渲染。

`tests/test_package_import.py`（18 个用例）覆盖材料包：新授权入库与原件下载、
同一 PDF 被多条授权引用只存一份、旧授权补件、补件遇已撤回授权不恢复、
同号冲突（署名/商用标记/原图不同）整包拒绝、CSV 内同号冲突、缺件拒绝且不留文件、
失败后重启再重传成功、重传内容不同拒绝/内容完全相同通过、多份原件逐份核对、
保存中断回滚与重传、大小上限、示例包导入、授权页下载链接。

另用 uvicorn + curl 手动试跑了真实流程：旧入口导入授权 → ZIP 补件（旧授权补挂原件、
同 PDF 多条授权）→ 下载原件比对 SHA-256 → 撤回后重传补件包（保持撤回，不恢复）→
缺件包失败且不新增授权/不留文件 → 修正包重传成功 → 重启服务后状态与文件仍在 →
大包上传中途断开（无入库、无残留文件）→ 完整重传成功。结果与上述一致。

## 未完成 / 说明

- 本环境没有 Docker，`docker-compose.yml` 与 `Dockerfile` 只做了静态校验，
  未实际构建镜像；应用本身已通过本地 uvicorn 全流程验证。
- 未做登录鉴权（编辑确认仅需填写姓名并留痕）；如需权限控制可前置反向代理或加登录模块。
- 不支持删除对照关系/展图、不支持删除已挂扫描件、不支持撤销撤回（撤回为终态）。
- 一个材料包只允许一份授权 CSV；包内未被 CSV 引用的 PDF 会提示并跳过，不入库。
- 同一授权号对应多份扫描件时，CSV 可写多行（原图、商用标记、署名须一致），
  每行指定一个 PDF；页面与 API 会列出全部原件。
- 清单下载固定列「原图号、授权号、署名」，如需扩展字段可在 `download_manifest` 中调整。
